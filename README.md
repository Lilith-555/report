# Сервис отчётов по качеству (Streamlit)

Локальное приложение для менеджера: загружаешь Excel с заданиями → получаешь наглядный дашборд и скачиваемый отчёт.

## Что делает

1. **Парсит комментарии проверяющего** по твоим правилам (мд, рп, грамматика, опечатки, систем, контекст, комментарий, единообразие, рекомендации).
2. Считает **качество в динамике** (по неделям).
3. Показывает **ошибки по критериям** (всего + heatmap по неделям).
4. **По каждому исполнителю**: сколько ошибок какого типа + примеры замечаний.
5. **Время**: из столбца + статус из комментариев (рекомендованное / допустимое / превышено).
6. **Мероприятия (ВКС)**: загружаешь отдельный файл или добавляешь вручную.
7. **Скачиваешь Excel-отчёт** с несколькими листами.

## Быстрый старт

```bash
cd quality_report_app
pip install -r requirements.txt
streamlit run app.py
```

Откроется браузер (обычно http://localhost:8501).

- По умолчанию включены **демо-данные** — сразу видно, как работает.
- Сними галочку «Использовать демо-данные» и загрузи свой Excel.

## Ожидаемые столбцы в основной таблице

Приложение пытается угадать названия. Лучше, если есть:

| Столбец              | Примеры названий                  |
|----------------------|-----------------------------------|
| ID исполнителя       | marker_id, id                     |
| Фамилия              | surname, фамилия, исполнитель     |
| Дата                 | date, дата, дата выполнения       |
| Качество             | quality, качество, оценка         |
| Время (мин)          | time, время, time_min             |
| Комментарий          | reviewer_comment, comment, комментарий |

Можно переопределить в сайдбаре.

## Файл мероприятий (опционально)

Столбцы примерно: `date`, `type` (индивидуальная / малая группа), `participants`, `topic`, `result`.

## Структура проекта

```
quality_report_app/
├── app.py              # Streamlit-интерфейс
├── comment_parser.py   # Логика разбора комментариев
├── requirements.txt
└── README.md
```

## Как доработать под себя

- Правила парсера — в `comment_parser.py` (словари `CRITERION_HEADERS`, `FREEFORM_KEYWORDS`, исключения).
- Новые графики / метрики — в `app.py` во вкладках.
- Если формат комментариев сильно отличается — пришли 5–10 реальных примеров, допилим regex.

## Вайб-кодинг

Это готовый каркас. Дальше можно:

1. Добавить фильтры по периоду / исполнителю.
2. Сделать PDF-версию отчёта (reportlab / weasyprint).
3. Подключить историю (сохранять предыдущие недели и сравнивать).
4. Вынести парсер в отдельный микросервис, если понадобится API.
